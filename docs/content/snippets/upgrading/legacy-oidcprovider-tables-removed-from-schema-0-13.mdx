### `oidcProvider` is no longer supported

Better Auth 1.7 removed the `oidcProvider` plugin. The Convex plugin used
`oidcProvider` internally to serve its OpenID discovery document. The component
now serves the discovery document itself, and the component schema no longer
declares the three tables `oidcProvider` added: `oauthApplication`,
`oauthAccessToken` and `oauthConsent`.

The discovery document now lists only the issuer, the JWKS URI and the token
capabilities that Convex and other relying parties need. The old discovery
document listed `/oauth2/*` authorization, token, userinfo, registration and
end-session endpoints, which the Convex plugin never served.

If your app added the `oidcProvider` plugin itself to act as an OpenID provider,
your app can no longer act as an OpenID provider. On Better Auth 1.7, an OpenID
provider requires compound unique indexes, which the Convex adapter doesn't
support: schema generation and the adapter throw an error if a plugin declares a
compound unique index.

**Upgrading deletes nothing.** When a schema stops declaring a table, Convex
keeps the table and its documents and stops validating them. In most apps the
three tables are empty, because the component never wrote to them, and you can
delete them from the component in the
[Convex dashboard](https://dashboard.convex.dev). If your app was an OpenID
provider, `oauthApplication` holds your registered clients, including client
secrets and redirect URLs; export `oauthApplication` from the dashboard before
you delete anything.
