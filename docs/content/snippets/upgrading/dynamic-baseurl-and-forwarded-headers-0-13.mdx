### Dynamic `baseURL` and forwarded headers

This step applies only to apps with a dynamic `baseURL`.

Better Auth 1.7 ignores `x-forwarded-host` and `x-forwarded-proto` unless
`advanced.trustedProxyHeaders` is set. You don't need to set it: the component
sets the request URL and `host` header itself, and Better Auth 1.7 reads them
instead. The Next.js and TanStack Start handlers need no changes.

If you run your own proxy in front of `.convex.site`, the component replaces any
`x-forwarded-host` and `x-forwarded-proto` your proxy sends, whether or not
`trustedProxyHeaders` is set. Send your public origin in
`x-better-auth-forwarded-host` and `x-better-auth-forwarded-proto` instead, and
list it exactly, without wildcards, in `trustedOrigins` or `allowedHosts`.
