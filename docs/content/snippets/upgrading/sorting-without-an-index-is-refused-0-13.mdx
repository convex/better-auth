### Sorting on a field without an index fails

A list sorted on a field no index covers now fails with an error that names
the index it needs. Before 0.13 these lists came back in creation order instead
of the requested order. This affects lists where the caller picks the sort
field, such as the admin plugin's `listUsers` sorted by `role` (or by `name`
while filtering by `role`) and the organization plugin's `listMembers` sorted
by `role`. Sorts that an index covers, including user lists sorted by
`createdAt`, `email` or `name`, work as before. Sorting by `id` isn't supported.

With [Local Install](/features/local-install#adding-custom-indexes), you can
add the index the error names.
